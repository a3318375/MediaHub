# 可选完善需求

本文记录可以继续讨论的完善方向，不是确定的开发计划，不承诺实现时间。是否开展取决于实际需求、维护成本与现有功能的稳定性。

## 首页、推荐与榜单

- 更符合 Dashboard 定位的首页：集中展示订阅更新、下载进度、整理结果、待处理异常与媒体库概况，提供常用操作入口。
- 电影、电视剧、动漫的推荐与排行：按内容类型提供推荐，便于发现想看的作品。
- 各种榜单：考虑热门、趋势、高分、新上映、季度动漫等，以及不同来源的特色榜单。
- 待讨论：首页以任务概况为主还是兼顾内容推荐；榜单按来源呈现还是统一入口。不同来源的评分与排名不宜直接混为同一个排名。

## 下载管理

- 更完善的任务列表、筛选、进度、队列与结果展示。
- 清晰区分离线下载、分享转存、文件确认及后续整理阶段。
- 完善失败原因、重试、停止跟踪与恢复操作，说明是否影响远端任务。
- 更方便地定位任务关联的作品、文件及目标目录。
- 待讨论：批量操作、并发控制、历史记录与通知的具体范围。

## 配置判断与提示

- 功能入口先判断必要配置，缺少配置时显示中文提示和前往设置的入口。
- 例如没有配置 TMDB 时，影视探索的 TMDB 来源直接提示需要配置，而不是请求后报错。
- 类似判断覆盖 Emby、115、通知等模块；一个服务未配置不应影响其他已经可用的来源。
- 区分未配置、凭证失效、网络不可达与上游异常，避免全部归为配置错误。

## 刮削与 STRM

- 可选考虑媒体刮削，如元数据、海报及 NFO，不一定实现。
- 刮削通常伴随 STRM 生成，需要结合完整媒体库流程评估，暂不承诺单独接入。
- 待讨论：只负责整理命名与作品关联，还是扩展 STRM、刮削与媒体库更新；与外部工具如何分工。

## 企业微信

- 企业微信作为可选通知渠道，不一定实现。
- 待讨论：群机器人通知是否足够，是否需要企业应用消息；根据实际需求选择接入方式。

## 其他网盘

- 评估 115 之外的下载、转存与文件管理能力，不一定接入。
- 搜索支持某个网盘，不代表已经支持该网盘的下载、转存或整理。
- 待讨论：具体网盘、认证方式、接口可用性、维护成本，以及是否需要统一多网盘任务模型。

## 美剧等剧集的持续订阅

- 动漫已有每日更新，考虑为美剧等持续更新的电视剧提供类似能力。
- 待讨论：与动漫合并为统一剧集订阅，还是保留单独页面与流程；暂不做决定。
- 需要评估资源来源、季集识别、匹配规则、更新频率、补集与完结判断的差异。
- 可以先考虑复用调度、下载记录与通知能力，再决定界面是否合并。

## 取舍原则

优先完善已有功能的体验和可靠性，再按需求扩展新能力。上述方向可调整、暂缓或取消，实施前再明确具体范围。
