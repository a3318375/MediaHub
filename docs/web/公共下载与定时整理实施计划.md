# 公共 115 下载、动漫渠道与定时整理实施计划

更新日期：2026-10-14（北京时间）。当前进度：公共下载、基础整理与四渠道已接入；最新产品方向改为设置中统一配置两个根目录、自动分类下载与归档，独立下载/整理菜单移除。整理与刮削分开，NFO/图片/STRM/Emby 刮削后置。验证主要使用模拟接口，真实 115/渠道/Emby 样本验收尚未执行；详见第 12 节最新记录。

本文件是后续工作的进度入口。首次要求仅记录需求；用户随后已授权按顺序实施。继续更新复选框、验证证据和遗留问题；未要求提交或推送，不创建自动化。

## 1. 已确定的方向

1. 动漫、电影等入口各自负责发现资源和选择下载内容，共用 115 下载能力；不能为每个入口重复实现 Cookie、离线任务、分享转存和文件接口。
2. 动漫订阅在规则匹配后触发公共下载。这里的 ani-rss 指本项目参考 ani-rss 的独立 Go 模块，不意味着部署外部 ani-rss 服务。
3. 整理是独立公共能力，覆盖电影、电视剧、动漫、节目等。提供启用开关、定时时间、未整理目录、整理后的目标目录、识别与命名规则，也可手动预览与执行。
4. 公共整理既处理本系统下载的文件，也能处理用户指定目录内已有文件；不能只能依赖某个下载器的完成通知。
5. RSS 刷新、下载提交、下载完成、整理完成、刮削完成分别记录。定时 RSS 刷新与定时整理是两套调度，不共享每日完成标记。
6. 115 使用 Cookie 接口，不采用 115 Open 授权路线。OpenList 普通 115 驱动可作为接口参考；LitePan 主要作为整理规划、文件操作和后处理的参考。
7. 命名和侧车文件以 Emby 能识别为目标，实施前核对 Emby 官方命名文档和参考刮削系统。本文中的目录例子是设计候选，不宣称已经验证兼容性。

## 3. 公共能力与业务边界

```text
Mikan / AniBT / AnimeGarden / 其他 RSS
    → 订阅、规则、主备选择 → 资源候选 ┐
电影/电视剧探索 → 资源搜索、人工选择 ├→ 公共下载服务
其他手动资源入口                   ┘      ├→ 115 磁力/链接离线
                                        └→ 115 分享转存
                                              ↓
                                   115 未整理目录 + 文件关联记录
                                              ↓
用户已有未整理目录 ─────────────→ 公共整理服务（定时或手动）
                                   → 识别/预览 → 网盘移动与改名
                                   → 元数据刮削 → 可选 STRM/刷库
```

建议职责（目录名称可在实施时调整）：

- `internal/pan115`：Cookie 客户端、限流、错误转换、离线/分享/文件 API，不包含订阅和影视命名逻辑。
- `internal/download`：公共任务、资源幂等、提交、完成确认、产物关联、恢复。输入含资源种类和可选作品上下文。
- `internal/organize`：来源扫描、身份匹配、计划、文件动作、调度与恢复；电影/剧集/动漫/节目策略共享执行器。
- 独立元数据/刮削服务：复用已有 TMDB/Bangumi provider，供整理调用，不能每个入口各写识别器。
- `internal/anime` / `animesync`：RSS 来源、规则和集数策略，调用公共下载服务，不直接操作 115 文件、不承担公共整理定时器。
- SQLite store 与 HTTP API：分别承载数据与鉴权/输入检查；前端提交意图、展示真实状态，不直接访问 115 凭证。

下载完成后可将产物标记为“待整理”，但默认按整理自己的定时配置执行。是否提供“完成后立即整理”作为额外触发方式是可选后续项；不得用它替代目录扫描。

## 5. 公共 115 下载

### 5.1 两种动作统一管理、分别实现

| 输入 | 实际动作 | 完成依据 |
| --- | --- | --- |
| magnet / 支持的离线链接 | 115 云端离线下载 | 外部任务状态 + 产物确认 |
| 115 分享链接及提取码 | 查询分享、选择文件、接收到自己的 115 目录 | 转存结果 + 实际目标文件确认 |
| 其他网盘分享 | 首版显示能力不支持，保留来源链接 | 不伪装成可直接转到 115 |

- [ ] 用统一 `kind` 区分 `offline`、`share_transfer` 等动作。115 分享不传给离线 URL 接口。
- [ ] 115 分享解析 shareCode、receiveCode 等信息，支持目录浏览、选中子目录/文件；过期、提取码错误、权限不足给真实原因。
- [ ] 分享接收可能同步或异步，适配层按真实响应处理。无百分比时显示“转存中/待确认”，不编造速度和下载进度。
- [ ] 同一 Cookie 账号的外部离线任务可按 hash 合并引用；不同业务入口关联各自意图。一个产物若被多个作品引用，进入冲突/复制策略，不能无条件重复移动。
- [ ] 不把分享源文件 ID 当成本账号接收后的文件 ID；转存完成后重新建立产物关联。

### 5.2 凭证、目录与接口适配

- [ ] 复用加密 `115.cookie`，被动验证登录和用户身份，区分失效、超时、限流、验证码/风控、空间或离线配额不足。
- [ ] 用 Cookie 路线参考 OpenList `drivers/115` 与 `SheltonZhu/115driver`，固定依赖版本；提交请求存在加密逻辑，不按旧文章随意拼表单。
- [ ] SDK 的登录检查、Context/取消、分页、逐项返回错误均需核对；不因 HTTP 200 或空 hash 认定提交成功。
- [ ] 未整理根目录保存稳定目录 ID + 显示路径；验证可读写和账号归属。路径改变后重新解析，网盘 ID 使用字符串。
- [ ] 任务隔离目录优先用于产物归属；是否使用每任务目录或按作品目录，通过真实接口验证决定。
- [ ] 全账号请求预算、提交并发限制、查询共享、退避；不全盘高频扫描。

### 5.3 公共任务与状态

候选状态：`queued → resolving → submitting → submitted → downloading/transferring → awaiting_files → completed`；另外保留 `failed`、`blocked`、`cancelled`、`unknown`。字段与 API 名称实施时定稿。

- [ ] 保存本地任务 ID、动作种类、幂等键、资源身份、业务引用、目标目录、外部任务 ID/hash、进度、时间、重试次数和错误类别。
- [ ] 保存作品上下文快照：媒体类型、provider/providerId、Bangumi/Mikan/TMDB ID、季、集、原始集数、偏移、字幕组、规则版本和来源详情。
- [ ] 提交超时属于“不确定”，先核对外部任务/目标文件，再决定重试，避免远端成功但本地重复提交。
- [ ] 按账号统一轮询离线列表并读取必要分页；参考字段有 `status`、`percentDone`、`rateDownload`、`size`、`file_id`、`wp_path_id`。
- [ ] 115 报告完成后确认实际文件/目录及视频清单，再记完成；百分比不是文件确认或整理完成。
- [ ] 外部任务消失时核对历史产物、隔离目录与文件 ID，进入待核对，不直接判失败或成功。
- [ ] 建产物表，保存本账号文件 ID、父目录、文件名、大小、文件 SHA1（如可用）及任务关联；BT infoHash 与文件 SHA1 不等价。
- [ ] 应用重启后恢复活跃任务与不确定提交，完成任务不重复下载；只管理本系统关联的任务，不清空账号离线列表。
- [ ] 暂停订阅表示停止产生新任务，不默认取消已有远端任务；停止监测不等于 115 支持暂停下载。
- [ ] 取消、删除离线记录、删除网盘文件分别表达；首版不自动删除用户已有媒体。

## 7. 公共定时整理

### 7.1 配置与调度

- [ ] 启用开关、北京时间每日时间/多个时间点、手动扫描、手动预览/执行、最近运行时间与结果；首版建议先每日时间，不直接开放任意 cron。
- [ ] 未整理目录支持多条规则，每条包含存储账号、源目录 ID/路径、递归范围、媒体类型提示、元数据来源偏好和对应目标目录。
- [ ] 目标可分别设置电影、电视剧、动漫、节目；动漫/节目可复用剧集规则，但媒体分类与命名结构是不同概念。
- [ ] 提供目录浏览选择和名称预览，实际操作使用稳定 ID；源/目标重叠、目标位于递归源内等循环风险验证并排除已归档目标。
- [ ] 限定扫描深度/数量、分页、缓存和增量水位；仅检查配置来源，不每天递归整个 115 账号。
- [ ] 同规则互斥，跨规则同文件不并发修改；批次和动作持久化；停机后只补当天必要批次，避免历史扫描风暴。
- [ ] 配置变更唤醒调度；失败退避；关机取消并等待服务退出；Cookie 失效暂停远端操作但保留待办。
- [ ] 定时整理按当前时间配置工作，下载完成只登记候选。日后可额外增加即时触发；不依赖通知开关。

### 7.2 文件是否可以整理

- [ ] 本系统下载文件：以任务真实完成和产物确认作为就绪依据，即使 RSS 已完结也继续整理。
- [ ] 用户已有文件：先按身份/类型扫描；人工可确认就绪。仅文件名/大小稳定并不能证明云端下载已完成；有活跃任务关联时继续等待。
- [ ] 对未知完成状态制定保守就绪策略和冷却时间，无法确定时保留在源目录并显示原因。
- [ ] 识别视频、外置字幕、已有 NFO/图片、样片/花絮、压缩包、蓝光结构和多文件种子。首版不支持的类型明确待处理，不静默丢弃。

### 7.3 身份和元数据来源

来源身份和刮削身份分开：Mikan/AniBT/AnimeGarden 提供资源与来源关联，Bangumi/TMDB 提供作品元数据。不能把 Mikan ID 当 TMDB ID，不能把 RSS 集数直接视为 TMDB 季集数。

当前本项目 Mikan 添加通过 Mikan 获取作品/字幕组关联，再用 Bangumi 填信息；已有 ani-rss 分析记录其使用 Bangumi，并可关联 TMDB 和剧集组。此前没有完成 Emby 全套兼容验证，后续需核对实现。

识别顺序建议：

1. 用户明确绑定的作品、季/剧集组与命名规则。
2. 下载时保存的作品上下文和文件产物关联；保留 Mikan/Bangumi 来源信息，避免文件整理时重新猜标题。
3. 文件/目录已有可信 provider ID、NFO 等元数据。
4. 解析文件名 + 年份 + 类型后搜索元数据；存在多个候选进入“待确认”。

- [ ] 电影默认 TMDB movie；电视剧/节目优先 TMDB tv；动漫保留 Bangumi 身份，可绑定 TMDB tv/movie。
- [ ] Bangumi 一条作品可能对应 TMDB 不同季/特殊集，建立显式映射；连续编号、分割季度、自定义偏移和剧集组可人工覆盖。
- [ ] 季与集映射分别记录，不能用单个 offset 解决所有跨季度/特别篇问题；保留原始信息。

### 7.4 命名、文件动作与刮削

候选结构（实施前按 Emby 官方规则验证）：

```text
电影/作品名 (年份)/作品名 (年份).mkv
电视剧或动漫/作品名 (年份)/Season 01/作品名 - S01E03.mkv
电视剧或动漫/作品名 (年份)/Season 01/作品名 - S01E03.zh-Hans.ass
特别篇/剧场版/按确认后的 movie 或 Season 00 映射处理
```

- [ ] 明确模板变量、padding、扩展名保留、非法字符、最大名称长度、provider ID、多版本/质量后缀；不把 Emby 识别规则写成随意的字符串替换。
- [ ] 节目可能按季集或日期命名，单独确认目标媒体库的支持方式；日期不能未经映射硬转季集。
- [ ] 视频/字幕配对，语言/forced/default 等后缀保留；多个视频不能全部套用 RSS 的单集编号。
- [ ] 规划与执行分离：保存源文件 ID、目标目录、目标名称、识别依据、规则版本、冲突和动作依赖；预览与执行使用同一计划。
- [ ] 115 内默认移动+重命名，可选复制；本地才考虑硬链接。当前 UI 默认“硬链接，失败时复制”不适用于网盘，需要按存储能力调整。
- [ ] 不覆写默认：同一产物已经到位则幂等跳过；同名不同内容记冲突，保留原文件；不能仅凭文件名或大小判定完全相同。
- [ ] 动作前复检冲突，动作后按文件 ID/父目录/名称验证；远端操作无原子事务，部分成功按动作日志恢复，不重做成功步骤。
- [ ] 整理失败仅重试整理；不会重新下载。未能识别的保留源目录，前端可人工选择作品和集数。
- [ ] 网盘列表延迟提供有限重查；首版不自动清理不明来源文件和非空目录。
- [ ] NFO/海报/季封面/单集信息的格式与文件名参考 Emby、ani-rss、LitePan 及其他刮削系统，核对后形成支持矩阵。
- [ ] 存在元数据时默认不覆盖；缺 provider/密钥时明确跳过或等待。共享作品级图片缓存，避免每集重复请求/上传。
- [ ] “已归档”“刮削完成”“媒体库已更新”独立状态；Emby 刷库/STRM 为可选后处理，不影响下载或基础整理成功。
