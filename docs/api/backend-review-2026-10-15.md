# 后端评审与修复记录：追剧、资源选择、公共下载

日期：2026-10-15。范围为电视剧订阅实现及其与 PanSou、TMDB、公共下载/整理的交界。包含针对既有公共下载入口的检查；不是整个系统的安全审计。

本文记录上一轮评审快照。之后的公开 TG 独立检索及按集补查更新见[当前实现说明](tv-subscription-scheduling.md)；私有账号监听与自动下载 outbox 仍未实现。

## 发现与本轮修复

| 优先级 | 触发场景与原问题 | 修复和验证 |
| --- | --- | --- |
| P1 | 自动解析媒体目录期间切换 115 Cookie，原 HTTP 入口随后可能以新账号入队，但目标来自旧账号 | 公共 `EnqueueToLibrary` 将目录解析与入队绑定为同一账号，并在远程调用后检查请求取消；加入切账号期间不得创建任务的测试 |
| P2 | 追剧仅能点原始链接，没有复用电影的下载流程 | 追剧资源接入同一个 `ResourceDownloadDialog` 和公共下载 API，传递订阅 ID、TMDB、季集；115 继续选文件转存，不默认整包转存 |
| P2 | 追剧允许短假 infohash、普通 115 页面、部分公共下载不接受的域名 | 抽出公共 `download.NormalizeLink`，复用 `NormalizeMagnet` 和 `ParseShare`；选择资格与公共下载保持一致，提取码保留，域名规范化 |
| P2 | 一条消息含多个作品/链接，正文被拼给每个链接，首个集数和全消息最大体积可能被误分配 | 适配层保留上游 `WorkTitle`；单链接消息才补全文，多链接仅使用各自标题和可确定信息，无法确定的体积保持未知 |
| P2 | 同一集先找到大体积 115，后续搜索又出现较小分享或磁力，原逻辑会降级覆盖 | 旧候选与新结果共同排序，保持 115 优先、同类体积优先和稳定 tie-break |
| P2 | `S01E01-E02`、多个单集标记被误当作第一集 | 单集初版拒绝明显多集/范围/歧义，不伪造单集关系；合集转存设计留到文件清单匹配阶段 |
| P2 | 刷新网络请求期间暂停/恢复，或删除后重建同 ID，旧结果可能覆盖新调度 | 增加持久化 revision 与创建时间校验；旧刷新不回写新实例/新版本；旧数据 revision 缺失按 0 兼容 |
| P2 | 用户给出的系统生成前瞻正则会被 Go `regexp` 拒绝 | 独立 `textmatch` 公共匹配器仅支持生成式正向 AND 子集，不引入通用回溯引擎；测试大小写、缺条件、转义、嵌套与拒绝不支持语法 |
| P3 | 改查询片名但规则没变，旧资源仍然保留 | 查询标题变化时清空已选候选并立即重新调度；元数据不再暗中改搜索标题 |

## 公共边界

- 来源适配器：获得候选和来源证据，不能直接转存、重命名或移动。
- `textmatch`：通用文本条件，供未来的直接 Telegram 来源和当前追剧复用。
- `download.NormalizeLink`：分享/磁力解析与规范化；不在追剧另造“宽松合法链接”规则。
- `download.EnqueueToLibrary`：媒体分类目录、账号绑定、校验与公共入队；同一任务状态机、去重、轮询、错误处理继续复用。
- `ResourceDownloadDialog`：电影、搜索与追剧共用；新增可选业务 reference，不复制 115 文件选择逻辑。
- 电视剧订阅：只保留 TMDB 排期、缺集、资源择优与订阅状态。没有强行将 RSS 动漫、网盘文件整理的不同业务语义合成一个大模块。

## 规范与注释复审

- 标题和正文会重复同一集号，原先按出现次数判多集会漏掉正常资源；改为按唯一季集判断，相同标记允许重复，不同集数或季数仍拒绝，补充回归测试。
- 修改已有订阅的作品/季数属于客户端错误，使用具名领域错误并返回 HTTP 400，不再笼统返回 500。
- TMDB 的缺失/空值 `episodes` 响应与正常空数组分开：前者作为上游格式错误，后者允许每日回退；避免把损坏数据当正常排期。
- 统一新增 Go 文件的标准库/第三方/本项目导入分组、函数间距；固定校验正则预编译，季集解析独立成可测试函数。
- 补充注释解释资源体积只是文本声明、正则兼容范围、刷新版本和创建身份校验、公共下载账号绑定及调度持久化；未为直白赋值和 CRUD 添加重复描述。
- 追剧列表请求支持取消与禁用浏览器缓存；新刷新中止旧请求，页面卸载取消请求，避免较慢轮询覆盖较新结果。修改操作期间统一限制重复操作。
- `.pnpm-store/` 加入常规忽略规则，避免将开发依赖缓存作为项目源文件提交。

## 仍需单独设计的风险/限制

1. **私有 TG 来源尚未实现。** 当前频道参数是 PanSou 公开频道；下一步需用户会话、权限检查、peer 解析、消息实体、断线恢复和持久化游标。详见 [两类订阅设计](../research/tv-subscription-sources.md)。
2. **自动下载 outbox 尚未实现。** 本轮接通的是公共手动下载。发现资源、下载入队、远端完成、整理成功应分开记录；不能以“找到链接”视为下载完成，也不应默认把整份分享视为单集。
3. **候选体积来自文本声明。** 单链接仍可能是整季总量；实际单集体积须在分享文件/磁力文件清单阶段确认。当前宁可未知，后续需显式 sizeSource 与可信级别。
4. **异步 PanSou 结果完整性。** 当前桥接会等待一次后读取缓存，不保证所有慢插件都完成。后续需要有完成状态的有界轮询或增量合并；不能用“加一个固定 sleep”宣称收齐。
5. **作品身份与歧义季集。** 当前以选定 TMDB 身份和标题搜索，尚未完整实现别名核验、绝对集数、季内集数、特别篇、合集映射；不能让 AI 或宽松正则静默补齐这些事实。
6. **手动下载回写日历。** 公共任务携带 season/episodes/reference，已提供后续回写依据；日历当前显示资源命中，没有把所有公共下载状态联动成已下载/已整理。
7. **历史数据里的失效链接。** 本次刷新会按公共解析规则重新筛选；没有直接批量重写用户数据库或清除旧订阅。账号与规则修改仍应与后续自动下载许可分离。

## 验证范围

本轮测试覆盖：合法/非法链接、115 与磁力优先级、跨刷新不降级、多集拒绝、前瞻子集、频道限制、原有按日期/每日回退、持久化、鉴权、并发规则编辑、暂停/恢复、删除重建、公共下载季集传递、去重、目录分类与切换账号保护。

验证命令：`go test ./...`、相关后端 `go vet`、前端构建和本轮修改文件的 ESLint。业务测试均使用本地 fixture，不声称私有 Telegram、真实频道历史或真实 115 下载已验收。未把用户的私有消息发给 AI，也未调用未授权榜单接口。
