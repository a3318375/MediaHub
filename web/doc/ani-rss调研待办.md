## 已确认的实现原则

- 每天北京时间 04:00 刷新数据库中启用、未完结、当天及前一天更新的订阅；不采用上游每轮结束等待 15 分钟的策略。
- 没有配置 115 Cookie 时，自动 RSS 与 Bangumi 任务不运行；配置保存后自动重新判断。这里判断的是凭证存在且可解密，不代表 115 登录有效，后续下载阶段需要验证。
- 手动单番剧刷新可在未配置 115 时读取 RSS/作品信息；已完结订阅不再读取上游。
- 完结按匹配规则后的有效整数单集覆盖 1..总集数判断，不直接按 Bangumi 播出完结，不用最大集数代替完整覆盖；累计保留历史覆盖，避免 RSS 滚动删除旧集数造成误判。
- RSS 更新、下载提交、下载完成、整理完成分别记录；发现资源不是已经下载。
- 电影与动漫复用统一下载和整理模块，动漫额外提供季、集数、字幕组、偏移与主备来源信息。

- [ ] 建立资源稳定身份：优先合法 infoHash，其次规范化下载地址/内容摘要；集数相同但资源版本不同需要保留来源与版本。
- [ ] 扩展标题集数识别、合集明确策略、OVA/剧场版、自定义剧集组和跨季度连续编号，保证预览与真实处理使用同一套解析。
- [ ] 自动偏移推断：上游 AniUtil.autoOffset 可分别推断主/备用 RSS；需要给出依据与人工覆盖，不静默推算。
- [ ] 规则作用域：上游用 `{{字幕组}}:` 前缀限定特定来源；当前规则全局应用，应在多字幕组策略中补充。
- [ ] 主备字幕组优先级、多字幕组共存、只追最新、延迟下载、漏集提示、禁止下载集数、优先关键词。
- [ ] 既有订阅规则编辑、删除、恢复误判完结、手动调整总集数、历史资源查看。
- [ ] AniBT/AnimeGarden 浏览与解析；按作品分组的批量添加、主备合并、逐条解析/重试/确认。
- [ ] 上游 HTML 结构漂移回归、空结果、慢响应、异常编码与长时间并发验收。

证据：`ItemsUtil.java` 合并主备、按正则过滤和按集数/文件名去重；`GroupRegexUtils.java` 固定识别词典，但组合来自实际发布标题；`BatchAdditionView.vue` 按作品分组，首来源为主，其余备用，逐条处理。

## 下载任务与 115 / tgtodriver（后续）

- [ ] 确定 tgtodriver 项目版本、API 与真实支持的磁力、种子、网盘转存通路；PanSou 命中链接不等于能跨盘转存至 115。
- [ ] 115 凭证有效性检查、失效与限流错误、目标目录选择，凭证仅保留后端。
- [ ] 统一任务模型：作品身份、资源身份、预计文件名/目录、目标存储、任务 ID、状态、失败原因、重试和幂等键。
- [ ] 按资源身份检查已有任务/已完成记录，下载前校验目标文件，避免同集重复或不同版本被误吞。
- [ ] 根据下载器能力提交磁力或种子文件，并返回真实外部任务 ID；提交成功与文件下载完成分离。
- [ ] 确认任务实际存在，失败有界重试；种子取得失败、任务提交失败、下载失败分别处理，不把提交当完成。
- [ ] 并发数量限制、暂停/取消、断点恢复与应用重启后恢复未完成任务。
- [ ] 为电影与动漫统一查询完成状态、取文件列表和稳定文件 ID；115 必须用实际文件 ID 重命名/移动。

上游证据：`ItemsUtil.java` 从 enclosure/扩展字段提取地址和 hash；`TorrentUtil.getTorrent/saveTorrent` 将磁力存为 txt、HTTP 种子存为 torrent，按 hash 保存重复记录；`BaseDownload` 提供统一 download/rename 等接口。qBittorrent 调用 `/api/v2/torrents/add`，磁力走 urls、种子走 torrents，携带 savepath/rename/category/tags，提交后轮询确认任务。Transmission 通过 RPC 提交磁力或种子；上游 Aria2 适配仅支持种子，不能据此宣称所有下载器同能力。`DownloadService.download` 默认配置允许 3 次提交尝试，最终失败删除本地种子记录让后续轮次能重试。

## 统一整理与下载后处理（后续）

- [ ] 统一目录/命名计划：作品、年份、季、集、字幕组及扩展名；先展示预览，再执行。
- [ ] 视频/字幕配对，保留语言后缀，可配置独立字幕目录；额外视频、重名文件和多版本需要冲突策略。
- [ ] 下载完成后登记文件产物与待整理关联，由公共整理按配置定时扫描（也支持手动预览/执行），再执行网盘内重命名、移动；后台重试可恢复，不依赖通知开关。
- [ ] 记录下载完成与整理完成两种状态；不能因首次发现/任务提交就将订阅标成已下载完结。
- [ ] TMDB/Bangumi 关联、可选剧集组，生成 tvshow.nfo/season.nfo/单集或电影 NFO、海报、季封面和缩略图。
- [ ] 生成的 NFO/图片上传 115，并以规则控制已有文件覆盖；缺 TMDB 映射或密钥时保留明确失败/跳过原因。
- [ ] 完结目录迁移、媒体库刷新、通知；失败不影响 RSS 发现历史，重试不重复移动。
- [ ] 主 RSS 替换备用源的洗版功能要单独确认删除/替换规则，默认不删除已有媒体。

上游证据：`RenameUtil` 生成名称，`BaseDownload.getFileReName` 保留视频扩展名/字幕语言后缀；qBittorrent 开启重命名时种子任务先暂停，用 renameFile 修改文件路径后 start/resume，不一定等下载完成；磁力等元数据可用再改名。Transmission 用 torrent-rename-path；Aria2 完成后移动本地视频/字幕。`RenameTask` 每轮默认间隔 10 秒，依次 rename/notification/delete。`DownloadService.notification` 先确认 finished 和完成标签，再刮削、发送完成事件和尝试完结迁移。`ScrapeService` 生成各级 NFO 与图片；`AniUtil.completed` 检查总集数、禁用、非 OVA 和全局/订阅迁移开关，修改下载器保存位置后移动残留文件。`NotificationUtil` 中 FILE_MOVE/OPEN_LIST_UPLOAD 等监听下载完成事件，受通知配置影响；我们应改成独立持久化后处理任务。
